## Proposed execution and rollback gate — requires approval

1. Confirm destination and standalone-example scope with the creator. Record
   HEAD, status and all seven live JSON hashes, plus protected canon/fixture
   hashes. Preserve unrelated edits. Check for pending generator recovery;
   complete verified recovery under the existing root before planning a move.
2. Relocate the approved demo as one reviewable change with all direct roots,
   imports, Vite paths, recovery exclusions, tests and current documentation.
   Preserve relative dataset references and bytes. Do not introduce a manifest,
   new-system CLI, loader refactor, calibration JSON or canonical conversion.
3. Run `npm test`, `npm run validate`, `npm run connections:check`, `npm run build`
   and relevant dev/production browser suites. Compare hashes and graph/gate
   freshness; audit production disclosure, base URLs and calibration exclusion.
   A stale graph after a pure path move is a discrepancy to investigate, not
   permission to regenerate authored output automatically.
4. If validation fails, reverse only the reviewed migration path/consumer edits
   using the recorded original bytes and mappings, preserving later user edits.
   Inspect concurrent changes before any overwrite. Generator journals/backups
   require the [manual recovery procedure](../../NAVIGATION_AUTHORING.md), never a
   blanket reset/clean. Restore a consistent root/import/audit/test set and rerun
   checks; leave protected canon and frozen fixtures untouched.
5. Return the path-by-path diff and exact results for review. No commit, push,
   deployment or automatic Phase 3 follows from Phase 2 authorization.
